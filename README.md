# SVI Control Panel — website

Static website for **svicontrolpanel.com** with a small server backend for the enquiry form.

- **Hosting:** Vercel (static files in `dist/`, functions in `api/`)
- **Enquiry storage:** Supabase (Postgres table `enquiries`)
- **Spam protection:** Cloudflare Turnstile
- **Optional:** email alert to the owner for each enquiry (Resend)

The site works **before** any of the services are set up: the form then opens WhatsApp or the
visitor's email app with the message already written. Once the variables below are set, it
switches to sending online automatically, with no code changes.

## Run it locally

Requires Node 22 or newer.

```bash
npm test                         # 8 server tests, no network needed
npm run dev                      # http://localhost:3000 — form in WhatsApp/email mode
MOCK_SERVICES=1 npm run dev      # form in online mode with simulated Turnstile/Supabase
```

For real local testing, copy `.env.example` to `.env.local` and fill it in (never commit it).

## Illustrations and photos

The panel, workshop and technician pictures are original vector illustrations generated by
`python3 source-assets/illustrations/build.py` (edit `panels.py`, `components.py` or `scenes.py`, then re-run).
They are deliberately drawn, not photo-like, so nobody mistakes them for SVI's own premises.

To use **real photos** instead, which is recommended once available, save a JPG or WebP
about 1200×800 px for each workshop step and point the matching `<img src>` in
`dist/index.html` at it (keep the same `width`/`height` ratio of 3:2, or update the attributes).
Product cards work best with a photo of the panel on a plain dark background, ratio 3:2.

## Motion and owner-controlled sections

**Motion:** the hero fades in with a slow zoom, sections slide in as they scroll into view,
counters count up, cards lift on hover, a thin amber bar shows reading progress, and lamps in
the drawings glow gently. All of it switches off for visitors whose device is set to reduce
motion, and all content stays visible if JavaScript fails.

These parts of `dist/index.html` wait for real information from SVI:

| Section | How to switch it on |
|---|---|
| **Counters** "Panels delivered" and "Customers served" | Put the real number in both `data-count="…"` and the text, then delete the word `hidden` on that line. "Years building panels" updates itself each year from 2009. |
| **Customer reviews** (`id="reviews"`) | Replace each `[placeholder]` with a real customer's words, name and company (with their permission), add or remove cards, then delete `hidden` on the `<div … id="reviews" hidden data-reviews>` line. The slider and arrows then work automatically. |
| **FAQ** (`id="faq"`) | Answers are drafts; edit the text inside each `<p>` once the owner confirms lead time, inspection visits and warranty. |

## Deploy (first time)

Create every account under the **company owner's email**, with the owner controlling billing,
recovery and two-factor authentication.

1. **GitHub** — create a private repository and push this folder (the `.gitignore` already
   excludes secrets). Keep `api/`, `dist/`, `lib/` and `vercel.json` at the repository root.
2. **Supabase** — create a project in a region near your customers (e.g. Mumbai).
   Open *SQL Editor*, paste `supabase/schema.sql`, run it. Check *Table Editor → enquiries* exists.
   From *Project Settings → API keys* copy the Project URL and a **secret** key.
3. **Cloudflare Turnstile** — in the Cloudflare dashboard add a Turnstile widget (Managed mode).
   Add the hostnames you will test on (the `*.vercel.app` address first, then the real domain).
   Copy the site key and secret key.
4. **Vercel** — *Add New → Project*, import the GitHub repository. Framework preset: **Other**.
   Leave the build command empty; the output directory comes from `vercel.json`.
   Vercel's Hobby plan is for non-commercial use only, so a business site needs a paid (Pro) team.
5. In Vercel *Project → Settings → Environment Variables* add:

| Variable | Value |
|---|---|
| `SUPABASE_URL` | `https://<project>.supabase.co` |
| `SUPABASE_SECRET_KEY` | Supabase **secret** key (server only, never in HTML) |
| `TURNSTILE_SITE_KEY` | Turnstile site key (public) |
| `TURNSTILE_SECRET_KEY` | Turnstile secret key |
| `SITE_HOSTNAME` | Hostnames the form is used on, comma-separated, no `https://` — e.g. `svicontrolpanel.com,www.svicontrolpanel.com,svi-website.vercel.app` |
| `CRON_SECRET` | Any long random string; protects the daily keep-alive |
| `RESEND_API_KEY` | *Optional* — turns on email alerts |
| `NOTIFY_EMAIL_TO` | *Optional* — who gets alerts, comma-separated |
| `NOTIFY_EMAIL_FROM` | *Optional* — leave blank until the domain is verified in Resend |

6. **Redeploy** (Deployments → ⋯ → Redeploy). Open the site: the form should show the security
   check and a **Send enquiry** button. If it still says "Send on WhatsApp", a variable is missing.

### Email alerts (recommended)

Without alerts, enquiries only appear in Supabase and someone has to remember to look.
Create a Resend account with the owner's email and add `RESEND_API_KEY` and `NOTIFY_EMAIL_TO`.
Until `svicontrolpanel.com` is verified in Resend, alerts can only go to the Resend account's
own email address. After verifying the domain (DNS records in Resend's dashboard), set
`NOTIFY_EMAIL_FROM`, e.g. `SVI Website <website@svicontrolpanel.com>`. Replies to an alert go
straight to the customer (reply-to is set to their email). An alert failing never loses the
enquiry; it is saved first.

### Keeping Supabase awake

Supabase pauses **Free-plan** projects that see too little database activity over a week. A
paused project makes the form fail. `vercel.json` schedules `/api/keep-alive` once a day to
prevent this (needs `CRON_SECRET`). Check it in Vercel *Settings → Cron Jobs*. The sure-fire
alternative is a paid Supabase plan, which is never paused and adds daily backups.

## Before launch — acceptance checklist

- [ ] `npm test` passes.
- [ ] On the Vercel URL: send a clearly labelled test enquiry; find the row in Supabase; get the alert email.
- [ ] Try invalid input (short message, bad phone, no consent): it is refused with a clear message.
- [ ] Check phone and desktop: menu, product "Enquire" links, Call/WhatsApp bar, links in the contact block.
- [ ] Owner confirms the content items listed in `REVIEW.md` → *Needs the owner*.
- [ ] Delete test rows from Supabase.

## Domain launch

1. In Vercel *Settings → Domains* add `svicontrolpanel.com` and `www.svicontrolpanel.com`.
   Pick one as primary (the code assumes `svicontrolpanel.com`) and redirect the other.
   If you choose `www`, change the canonical/og URLs in `dist/index.html`, `dist/privacy.html`,
   `dist/robots.txt` and `dist/sitemap.xml`.
2. Note the current DNS records first. Add only the records Vercel shows. **Keep all MX and
   mail-related TXT records** (SPF, DKIM, DMARC) so company email keeps working.
3. Add the domain(s) to the Turnstile widget and to `SITE_HOSTNAME`; redeploy.
4. Check HTTPS on both names, the redirect, a live enquiry, and that business email still works.

## Owner routine

Supabase → *Table Editor → enquiries*. Newest first. Change `status` from `new` to `contacted`
or `closed`; use `notes` for anything internal. Agree how often leads are checked and how long
they are kept, and delete old rows accordingly. Export a CSV backup now and then.

## Troubleshooting

| Symptom | Check |
|---|---|
| Form shows "Send on WhatsApp" on the live site | A required variable is missing or misspelt; redeploy after fixing |
| "Security check failed" | Hostname missing from Turnstile widget or `SITE_HOSTNAME`; keys from different widgets |
| "We could not confirm delivery" | Vercel function logs; Supabase URL/secret key; table created; project paused? |
| No alert emails | `RESEND_API_KEY` / `NOTIFY_EMAIL_TO`; sender domain verified; spam folder |

Never paste keys into chat, Git, or the HTML. After hand-over, remove temporary collaborators
and rotate any keys that were shared.
